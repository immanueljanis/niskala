# Architecture

## Components

```
┌──────────────┐  Web3.js (injected)   ┌────────────────────────────┐
│  apps/web    │ ─────────────────────▶│  RfqMarket.sol (Monad)      │
│  Next.js 16  │  createRfq / execute  │  · RFQ rounds + commitments │
│              │◀───── reads ──────────│  · maker WETH vault         │
└──────┬───────┘   Web3.js (RPC)       │  · submitProof → verifier   │
       │ REST (chain + offchain view)  │  · atomic settlement        │
       ▼                               └──────────┬─────────────────┘
┌──────────────────────────────────────┐          │ verify(bytes, bytes32[10])
│  apps/coordinator (Node)             │          ▼
│  · makers.ts  3 wallets, private     │  ┌────────────────────┐
│    strategies → commit tx each       │  │ HonkVerifier.sol   │ generated by bb.js
│  · watcher.ts polls chain, collects  │  │ (UltraHonk, keccak)│
│    openings, proves, relays proof    │  └────────────────────┘
│  · packages/zk  noir_wasm + bb.js    │
│  · api.ts   never exposes openings   │
└──────────────────────────────────────┘
```

## Round sequence

1. **createRfq(amountOut, commitWindow, settleWindow)** — trader wallet. Status `OPEN`. Event `RfqCreated`.
2. **commit(rfqId, commitment)** ×3 — each maker wallet. Requires registered maker, open window, no duplicate,
   `available(maker) ≥ amountOut`; locks `amountOut` WETH. Slot order = arrival order. At 3 commitments the
   round flips to `COMMIT_CLOSED` (`CommitPhaseClosed`). `closeCommit` after the deadline cancels an incomplete round.
3. **Opening delivery** — each maker hands `(priceE6, salt)` to the coordinator in-process (persisted to `data/rounds.json`).
4. **Proof** — coordinator selects the first-minimum winner, executes the Noir circuit (noir_js witness),
   proves with `UltraHonkBackend.generateProof(witness, { verifierTarget: "evm" })`, verifies locally.
5. **submitProof(rfqId, winnerIndex, winningPriceE6, proof)** — relayer wallet (permissionless). The contract
   builds `publicInputs = [DOMAIN, rfqId, makers[3], commitments[3], winnerIndex, winningPriceE6]` from storage and
   calls `HonkVerifier.verify`. Status `PROVEN`, `BestExecutionProven(rfqId, winnerIndex, winner, price, keccak(proof))`.
6. **execute(rfqId)** — trader wallet, before `settleDeadline`. `cost = amountOut × priceE6 / 1e18`;
   `USDC.transferFrom(trader → winner, cost)`, `WETH.transfer(trader, amountOut)` from the winner's vault balance,
   all locks released. Status `SETTLED`.
7. **expire(rfqId)** — anyone, after `settleDeadline`, for `COMMIT_CLOSED`/`PROVEN` rounds: cancel + unlock.

## Circuit (`circuits/best_quote/src/main.nr`)

```
main(domain: pub Field, rfq_id: pub Field, makers: pub [Field;3], commitments: pub [Field;3],
     winner_index: pub u32, winning_price: pub u64, prices: [u64;3], salts: [Field;3])
  winner_index < 3
  ∀i: prices[i] > 0
      Poseidon2::hash([domain, rfq_id, makers[i], prices[i], salts[i]], 5) == commitments[i]
      winning_price <= prices[i]
      i < winner_index ⇒ winning_price < prices[i]        // deterministic tie-break
  winning_price == prices[winner_index]
```

- Poseidon2 from `noir-lang/poseidon` v0.4.0 (vendored); the same hash in JS via `bb.js` `poseidon2Hash`.
  Consistency is enforced by test: a JS-computed commitment must be accepted by the circuit.
- `domain = (chainId << 160) | market` fits the BN254 field without hashing and binds every commitment to one deployment.
- Circuit size: 226 proof fields, 7,232-byte proof, verification key 1,888 bytes.

## Toolchain notes (Windows host)

- No Windows `nargo`/`bb` binaries exist for Noir 1.0.0-rc.3. Compilation runs through `@noir-lang/noir_wasm`
  (with a POSIX-path shim, see `packages/zk/src/compile.ts`) and proving through `@aztec/bb.js` 5.2.1 WASM.
  `nargo test` is additionally run in WSL for the circuit's own unit tests.
- `bb.js` `getSolidityVerifier` emits `HonkVerifier.sol` (ZK variant, keccak transcript). Compiled with solc 0.8.28,
  optimizer 200 runs, evm `cancun`, 18.3 KB runtime.

## Coordinator API (read-only)

| Route | Returns |
|---|---|
| `GET /api/health` | chain id, addresses, block, maker roster (public fields only) |
| `GET /api/makers` | roster |
| `GET /api/rfq/:id` | `{ chain, offchain, makers }` — chain state + commit tx hashes, phase, proof summary (hash, size, timings, tx) |
| `GET /api/rfq/:id/proof` | raw proof bytes + public inputs (both public data) |

`rounds.publicView()` strips `openings` before anything is serialized. There is no endpoint that returns a losing price.

The watcher polls `rfqCount` + `getRfq` for the last 8 rounds every 1.5 s (no log subscriptions). Trader transaction
hashes for the receipt (`RfqCreated`, `RfqSettled`) are found with `eth_getLogs` in 100-block windows, because the public
Monad RPC rejects wider ranges; the scan cursor is persisted per round so it resumes instead of re-scanning.

## Frontend data flow

- `useRound` polls the coordinator every 1.5 s; if it is unreachable, falls back to `getRfq` over the public RPC
  so the page still reflects chain truth.
- Wallet actions go through `src/lib/chain/contracts.ts` (createRfq, approve, mint, execute). Components never touch ABI calls.
- Network config lives in `src/lib/chain/network.ts` with the official Monad testnet values and `NEXT_PUBLIC_*` overrides.

## Gas and timing (measured)

| Step | Gas (anvil) |
|---|---|
| createRfq | ≈ 150 k |
| commit | ≈ 130 k |
| submitProof | ≈ 3.5 M (2.4 M execution + proof calldata); Monad testnet receipts report ≈ 5.8 M |
| execute | ≈ 120 k |

Monad charges `gas_limit × gas_price`, so the relayer pays ≈ 0.6 MON per proof at the 102 gwei testnet price;
`pnpm setup:monad` funds it with 1.5 MON and the faucet adds 5 MON per request.

Proof generation 0.5–3 s on a laptop (WASM, 8 threads); first proof after start ~1 s extra for backend warm-up.
